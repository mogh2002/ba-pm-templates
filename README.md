# BA & PM templates

Plain Markdown templates I use for business analysis and project delivery. Copy one, fill the blanks, delete what you don't need.

Each template is short on purpose: one page you can read in two minutes beats a 20-page form nobody fills in.

| Template | Use it when |
|---|---|
| [Project charter](templates/project-charter.md) | Starting anything that takes more than a week |
| [Weekly status report](templates/weekly-status-report.md) | Every week, to your manager or client |
| [RACI](templates/raci.md) | People aren't sure who does what |
| [Risk log](templates/risk-log.md) | From day one; review it weekly |
| [Note triage guide](templates/note-triage-guide.md) | After a UAT, sprint review or client session: sorting notes into Bug / Tweak / CR |
| [Handover card](templates/handover-card.md) | Someone leaves or changes project; one card per piece of work |
| [Lessons learned](templates/lessons-learned.md) | At the end of a project or phase |

## Worked example

[`examples/clinic-portal-handover/`](examples/clinic-portal-handover/) shows the charter, a status report and a handover card filled in for a **made-up** project (a clinic booking portal). All names and numbers in it are invented.

## Principles behind these templates

1. **Lead with the answer.** The first line of every document says the decision, status or result.
2. **Specific over vague.** Dates, names, numbers. "Soon" and "some issues" are not status.
3. **Every open item has an owner and a date.**
4. **"Done" is defined before work starts** (success criteria in the charter).
5. **No secrets in documents.** Name the account or system; never the password.
